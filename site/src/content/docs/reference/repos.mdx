## 当日コア（午前〜午後で使う）

ここにないものは、必要になったタイミングで上のプロンプトを使って判断してください。

| リポジトリ | 研修での使いどころ | なぜ使うか | リンク |
|---|---|---|---|
| `upstash/context7` | ライブラリやAPIの調査・実装 | AIの記憶ではなく、**今の公式ドキュメント**を見ながら判断するため | [GitHub](https://github.com/upstash/context7) |
| `openclaw/gogcli` | Sheets / Drive 連携デモ | スプレッドシートを自然言語から作り・更新する入口になるため | [GitHub](https://github.com/openclaw/gogcli) |
| `teng-lin/notebooklm-py` | 資料置き場として NotebookLM を使う | 毎回PDFや記事を貼らず、**資料群を参照する入口**を作るため | [GitHub](https://github.com/teng-lin/notebooklm-py) |
| `unclecode/crawl4ai` | WebページをInputにする | 公開ページをMarkdown化し、Codexで要約・比較・業務フロー化に使うため | [GitHub](https://github.com/unclecode/crawl4ai) |
| `garrytan/gbrain` | 合宿後の記憶運用 | 判断履歴・業務ナレッジを蓄積し、次回のAIが過去の文脈を引き出せる状態を作るため | [GitHub](https://github.com/garrytan/gbrain) |

<Callout variant="note" title="agent-browser は本流外">
  HTMLのUI確認用 `vercel-labs/agent-browser` は一覧に載せていますが、Windows Defender 等で当日詰まるリスクがあるため**研修本流では使いません**。必要になったら下の「エージェント・スキル関連」から判断してください。
</Callout>

## MCP — 目と手を増やす

MCP（Model Context Protocol）は、Codex に**外部ツールへの接続口**を足す仕組みです。

| リポジトリ | 用途 | 難易度 | リンク |
|---|---|---|---|
| `upstash/context7` | 最新ライブラリのドキュメントをリアルタイム参照。GAS・React 等の調査に | 易 | [GitHub](https://github.com/upstash/context7) |
| `exa-labs/exa-mcp-server` | Web・X投稿・コードを高精度検索。裏取りや競合調査に | 易 | [GitHub](https://github.com/exa-labs/exa-mcp-server) |
| `github/github-mcp-server` | Issue / PR / リポジトリ情報を Codex から参照 | 中 | [GitHub](https://github.com/github/github-mcp-server) |
| `chrome-devtools-mcp` | ブラウザの DOM・コンソール・ネットワークを確認。HTMLアプリの検証に | 中 | [npm](https://www.npmjs.com/package/chrome-devtools-mcp) |

## 使い方の原則

1. **当日コアだけ先に通す** — 上の5つを優先。残りは必要になってから。
2. **1つ入れて動作確認してから次** — まとめて入れると、どこで詰まったか分からなくなる。
3. **詰まったらエラー全文を貼る** — ログを省略せず Codex に渡す。[詰まったら](/start/stuck/) も参照。
4. **導入判断を省略しない** — 「便利そう」だけでは入れない。用途・リスク・代替を整理してから入れる。
