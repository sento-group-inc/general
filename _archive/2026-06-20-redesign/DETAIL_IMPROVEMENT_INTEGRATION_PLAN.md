> 作成: 2026-06-20

## 1. 根本意図

今回の依頼は「このページの文言を直す」ではなく、教材サイトが以下の状態に戻ることを求めている。

- 受講者が当日やることだけが載っている
- 事前準備、設定、体験、命名、振り返りの順番が自然
- 和島が口頭でやる実演や補足を、資料本文が先回りしない
- 研修中に作るログやフォルダが、最後の振り返りで回収される
- 重複、不要ツール、過剰説明、見づらい重要メッセージをテストで潰す

要するに、サイトは「説明集」ではなく「講義進行と受講者体験のレール」である。

## 1b. 初回依頼から見た背骨

この研修は、単なるCodex操作研修ではない。

表の目的は、Codexを業務で使える状態にすること。裏の背骨は、参加者が「AIに何を向けるか」を自分で判断し、粗く出して改善し続ける習慣を持ち帰ること。

sento.group / 和島がやる意味は、資料本文で売り込まない。体験を通じて「AI活用の見方を変えた最初の人」として残るように設計する。依存形成ではなく、自走支援として効かせる。

### 体験の山

- Day1 AM: 安全と好奇心。セキュリティ設定と自由探索で、まず触れる状態を作る。
- Day1 PM: Mermaid / IPOA。粗いv1を出し、Inputを足すとv2が変わる改善の快感を作る。
- Day2 Last: 100選と成果物一覧。2日で作った量を一望し、継続更新で良くしていく確信を残す。

### TOC業務棚卸し

TOCは和島が現場でリードする独自の進行が価値。教材側は細かく書きすぎない。

ざっくり流れだけ示す:

1. 5分間、課題や不満を大量に書き出す
2. 分類する
3. 時系列に分解する
4. IPOAに分解する
5. Stateに分解する

資料が進行を奪わず、和島のファシリテーションで場を動かす。

### 100選エンジン

100選は「記録」ではなく、改善習慣を残す仕組み。

Day2最後に「2日でAI活用100選と成果物一覧を作った。ここから継続更新しながら良いものにしていくことが大事」という本質を伝える。完成品として閉じず、継続的に更新していく器として終える。

### 本流から下げるもの

- 性格診断 / 占い / ホロスコープ: おかわり課題。複数Inputで輪郭が出る体験は、業務版としてMermaid / IPOAに継承する。
- Firecrawl / agent-browser 系: 全員必修にしない。環境詰まりが大きいので、軽量取得または講師デモに限定する。

## 2. 設計原則

1. 当日使わないものは消す
   - Git / GitHub / Vercel は事前準備・講義本文から外す。
   - 実演は和島がその場で行うものとして、資料には操作課題化しない。

2. 初期に詰まりを潰す
   - `/start/` に目的共有、事前準備、スケジュールを集約する。
   - 「詰まったら」ページを前半に用意し、スケジュール内の注意書きから独立させる。
   - 研修フォルダは SharePoint に自分の名前で作る。

3. 体験してから命名する
   - ⑨ Codex習熟 → ⑩ Mermaid改善ループの順序を維持する。
   - 「先に体験、後で命名」などのメタ文言は本文に出さず、実際の構成で示す。

4. 伏線を最初に仕込んで最後に回収する
   - `learning-log/` は初期セットアップで作る。
   - AGENTS.md に「各区切りで learning-log に残す」運用ルールを入れる。
   - Day1/Day2の振り返りは、すでに溜まったログを読む構成にする。

5. 設定説明は操作対象ごとに独立させる
   - 一般設定、作業モード、権限、カスタム指示、プラグインを混ぜない。
   - プラグインは後半に独立ページを作り、Box / SharePoint の接続設定まで扱う。

6. 重要メッセージは視認性で勝たせる
   - `/day-1/purpose/` の「2日間でCodexを学び、自分の業務で使い始める」を最重要メッセージとして大きく扱う。
   - 似た内容のカード・見出し・ページを並べない。
